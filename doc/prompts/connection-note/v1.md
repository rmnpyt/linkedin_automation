# Connection Note Prompt — v1

**Role:** LLM generation step for a qualified candidate's personalized LinkedIn connection
request note (PLAN.md sec.18, CONTRACT.md sec.41.1,44, CONNECTION-FLOW.md "Connection-note
drafting").

**Precondition (enforced by the caller, not this prompt):** this step MUST only run for a
candidate whose current governing Evaluation is `COMPLETE`, `qualified = true`, and still
within the 30-day freshness window (CONTRACT.md sec.25). An incomplete or disqualified
evaluation MUST NOT reach this step (CONTRACT.md sec.20.1,44).

**What this step does and does not do:**
- It writes ONE short, genuinely personalized note (LinkedIn connection notes have a strict
  character limit — keep it under 300 characters) referencing the *specific, real* reason
  this candidate matched the campaign.
- It does not decide qualification, does not compute any score, and does not choose whether
  to send. It only drafts text, given a decision that has already been made.
- It must never produce a generic, context-free note ("I'd like to add you to my
  professional network") — CONTRACT.md sec.44 explicitly says a generic note does not
  satisfy the requirement.

---

## System prompt

```text
You write short, genuine LinkedIn connection-request notes. You will be given:
1. The campaign's objective (why this operator is reaching out to this kind of person).
2. The candidate's profile evidence (headline, role, location, relevant experience text).
3. The specific KPI reasons that qualified this candidate — these describe the REAL,
   concrete reason this person matched (e.g. a specific project, a specific location, a
   specific role).

Write one connection-request note that:
- Is under 300 characters (LinkedIn's connection-note limit).
- References at least one SPECIFIC, real detail from the profile evidence or KPI reasons
  — not a generic compliment, not a vague "I saw your profile."
- Sounds like a real, brief, professional message a person would actually send — not
  marketing copy, not a form letter.
- States a genuine, legible reason for connecting, consistent with the campaign objective.
- Does not overstate familiarity (do not claim to know the person, have met them, or have
  a mutual connection unless that is explicitly given as evidence).
- Does not fabricate any fact not present in the given evidence.

Respond with ONLY the JSON object described below — no prose before or after it.
```

## Required output schema

```json
{
  "note": "Hi Alice — noticed your work on computer-vision for wildlife camera-trap data at Acme Robotics. I'm building a network of people doing applied ML in that space and would love to connect.",
  "reasoning": "Referenced the specific animal-related project from KPI 4's reason, kept it under 300 chars, no overstated familiarity."
}
```

- `note`: the exact text to persist as `connection_note.body` and eventually send. Must be
  a non-empty string under 300 characters.
- `reasoning`: a short internal explanation of which evidence was used (for
  provenance/debugging; not sent to LinkedIn, not required to be persisted verbatim but MAY
  be stored in `connection_note`'s trace metadata).

## Caller responsibilities (not part of the prompt itself)

- Validate `note` is non-empty and under LinkedIn's character limit before persisting;
  malformed output MUST be retried or marked failed, never silently coerced
  (CONTRACT.md sec.24's spirit applied here).
- Persist the note via the database's `create_connection_note_and_mark_ready` function
  (supabase/migrations), which independently re-verifies the evaluation is COMPLETE,
  qualified, fresh, and still the candidate's current governing evaluation before allowing
  the note to be created and the Connection to reach `NOTE_READY` — this prompt/generation
  step MUST NOT be trusted as the sole gate for those invariants (CONTRACT.md sec.69).
- Record `prompt_version = "connection-note/v1"`, model provider/name, and the trace_id
  alongside the note (CONTRACT.md sec.41.1).
